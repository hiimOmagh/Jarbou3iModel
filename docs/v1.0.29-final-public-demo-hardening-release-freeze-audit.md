# v1.0.29 — Final Public Demo Hardening / Release Freeze Audit

v1.0.29 hardens the public-demo evidence trail after the hosted screenshots were reviewed. The observed weakness was not a product capability defect: the page rendered, CI was green, and the evidence files existed. The release weakness was evidentiary: `hosted-demo-metadata.json` could be overwritten by separate browser tests, leaving only a partial capture list while screenshots existed elsewhere in the artifact folder.

## What changed

- The hosted-demo evidence browser test now writes one final metadata artifact after capturing all required states.
- The metadata includes the complete required capture list: desktop first screen, mobile first screen, provider mode, and quality/export.
- Each capture records viewport dimensions, PNG dimensions, byte size, full-page mode, and horizontal-overflow sanity.
- A no-browser gate now checks the evidence-manifest discipline before browser CI runs.
- v1.0.28 release provenance remains preserved as historical release context.

## What did not change

- No live scraping or live source verification was added.
- No production OAuth was enabled.
- No provider, backend, source connector, or storage behavior changed.
- Manual/private mode remains the release default.
- Browser evidence remains inspection material, not automatic release approval.
