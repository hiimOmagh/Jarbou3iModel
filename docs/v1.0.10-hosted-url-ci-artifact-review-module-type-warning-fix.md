# v1.0.10 — Hosted URL CI Artifact Review + Module-Type Warning Fix

v1.0.10 rebuilds the failed-download patch from the confirmed v1.0.9 baseline. It keeps runtime behavior stable while making hosted-demo CI artifacts easier to review and removing Node's module-type warning in backend smoke validation.

## Scope

- Declare package-level ESM mode with `"type": "module"` in `package.json`.
- Keep the Cloudflare Worker smoke path warning-clean when imported by Node tests.
- Add `tests/module-type-warning-fix-check.mjs` to prove the warning is not present.
- Add `tests/v110-no-browser-suite.mjs` as the canonical patch suite for this release.
- Keep hosted URL browser evidence capture and GitHub artifact upload from v1.0.9 intact.
- Keep release docs, manifest, fixtures, schema, and migration snapshots aligned with v1.0.10.

## Compatibility boundary

No provider, OAuth, backend endpoint, source connector, storage, or browser runtime behavior changed. The patch is release/CI hygiene only.

## Why this patch exists

v1.0.9 passed no-browser gates but emitted a Node warning during `tests/backend-worker-smoke.mjs`:

```text
MODULE_TYPELESS_PACKAGE_JSON
Reparsing as ES module because module syntax was detected.
```

The warning was caused by ESM syntax in the Worker and config files while `package.json` did not declare module mode. The repo already uses ESM syntax, so package-level ESM is the compatible fix.
