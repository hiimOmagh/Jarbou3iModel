# v1.1.0-alpha.2 — Expansion Lane Acceptance Criteria Matrix

## Release purpose

This release converts the post-freeze planning lanes from v1.1.0-alpha.1 into an explicit acceptance criteria matrix. It is still a planning gate only. It does not implement a provider, OAuth, backend, source connector, live search, storage, or public-demo capability expansion.

## Baseline

- Previous alpha gate: v1.1.0-alpha.1 — Post-Freeze Product Expansion Planning Gate
- Public-demo freeze baseline: v1.0.30 — Mobile Header Geometry Lock / Final Public Demo Visual Freeze
- Current track: v1.1.0-alpha.2
- Release type: alpha planning gate

## What changed

v1.1.0-alpha.2 adds lane-level decision structure before any implementation work:

- lane owner / decision domain;
- acceptance criteria;
- falsifiers;
- evidence requirements;
- blocked-until gates;
- readiness scoring;
- explicit implementation blocking.

## Expansion lanes covered

1. UX polish and density reduction
2. Real provider path threat model
3. Source and evidence strategy
4. Privacy/security hardening backlog
5. Release operations and artifact discipline

## Planning gate only

implementation remains blocked. A lane can move to implementation only in a later version that updates code, tests, docs, fixtures, and browser evidence together.

## Preserved boundaries

- No live scraping.
- No real OAuth.
- No live provider execution.
- No backend endpoint expansion.
- No source connector expansion.
- No storage model change.
- No automated source verification.
- Manual/private mode remains the default.
- Source packets remain local/manual drafting scaffolds unless a later implementation release changes that with explicit tests.

## Blocked claims

Do not claim any of the following in public demo material:

- live web scraping;
- production OAuth/account login;
- automated source verification;
- real provider execution;
- source connector automation;
- implementation approval from criteria alone;
- release approval from screenshots or ZIP existence alone.

## Acceptance criteria

- `package.json` and `package-lock.json` identify `1.1.0-alpha.2`.
- `index.html` shows `v1.1.0-alpha.2 · Expansion Lane Acceptance Criteria Matrix`.
- `src/research/post-freeze-planning-gate.js` exports lane criteria, falsifiers, evidence requirements, and blocked-until gates.
- Every lane has at least three acceptance criteria and two falsifiers.
- Every lane has `implementation_allowed: false` and `capability_expansion: false`.
- v1.1.0-alpha.1 and v1.0.30 artifacts remain present as baselines.
- migration support includes `1.0.30`, `1.1.0-alpha.1`, and `1.1.0-alpha.2` in order.
- no-browser CI runs `tests/expansion-lane-acceptance-matrix-check.mjs`.

## Disproven if

This release is invalid if it enables any runtime capability, exposes a planned lane as a usable feature, removes the v1.1.0-alpha.1 or v1.0.30 baselines, weakens provider/OAuth/source/privacy/export boundaries, or allows implementation before lane criteria and falsifiers are explicit.
