# v1.0.14 — Evidence Scoring v1

## Summary

v1.0.14 adds a conservative evidence scoring layer that separates public attention from evidentiary reliability before synthesis. This patch does not add live scraping, production OAuth, backend endpoint changes, provider behavior changes, or source connector expansion.

## What changed

- Added `src/research/evidence-scorer.js`.
- Added per-evidence `evidence_scoring` metadata.
- Added packet-level `evidence_scoring_report`.
- Added schema support for `evidence_scoring.v1`.
- Updated manual source import and source-packet import paths to score imported candidates while preserving the review queue boundary.
- Updated Quality Gate v3 with reliability and attention-integrity dimensions.
- Updated fixtures, migrations, privacy export fixture, release docs, and no-browser CI coverage.

## Scoring model

Evidence Scoring v1 tracks:

- `attention_signal_score`: public/engagement signal only.
- `reliability_score`: traceability, source class, specificity, confidence, and recency.
- `traceability_score`: URL/title/date/source metadata presence.
- `specificity_score`: claim specificity and evidence strength.
- `recency_score`: temporal relevance.
- `contradiction_value_score`: whether the evidence helps test or weaken assumptions.
- `synthesis_weight`: bounded synthesis weight, not a truth score.

Critical policy:

```text
attention_signal_is_not_evidence_reliability
```

## Guardrails

- Attention is never treated as truth.
- High-engagement social evidence is flagged for corroboration.
- Weak traceability is flagged before publication.
- Imported candidates remain review-gated.
- No live fetching is added.
- No OAuth behavior is added.
- No provider behavior is changed.
- No backend endpoint is changed.
