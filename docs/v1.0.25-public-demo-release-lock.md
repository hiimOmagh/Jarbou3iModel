# v1.0.25 — Public Demo Release Lock

## Purpose

v1.0.25 locks the public demo release decision. It converts the current manual/private demo boundary into an explicit release gate: CI must be green, hosted-demo evidence must be reviewed, public claims must match available features, and unavailable capabilities must remain clearly blocked.

## What changed

- Added `public_demo_release_lock` metadata to research workflow packets.
- Added schema and fixture coverage for the release-lock object.
- Added `tests/public-demo-release-lock-check.mjs` and `tests/v125-no-browser-suite.mjs`.
- Added package scripts for `test:public-demo-release-lock`, `test:v125:no-browser`, and `test:v125`.
- Updated current release docs, release notes, manifest, roadmap, QA matrix, and public-demo operator guide.

## Release lock invariants

- Manual/private mode remains the default.
- Browser evidence is inspection material, not standalone approval.
- Screenshots alone are not sufficient for release approval.
- ZIP existence alone is not sufficient for release approval.
- No live scraping, live source verification, production OAuth, provider expansion, backend expansion, or storage expansion is introduced.
- Source packet templates remain local/manual drafting scaffolds.

## Approval requirements

```bash
npm run test:public-demo-release-lock
npm run test:v125:no-browser
npm run test:ci:no-browser
npx playwright install --with-deps
PLAYWRIGHT_SKIP_INSTALL=1 npm run test:ci:browser
```

## Stop condition

Do not publish the public demo if the intended release commit lacks green no-browser CI, green browser CI, reviewed hosted-demo evidence, current release metadata, or public documentation that clearly separates available capability from blocked future capability.
