# v1.1.0-alpha.3 — Repository Consolidation Audit + Retention Registry

## Release type

Alpha audit gate. This release is audit-only.

## Purpose

The repository has accumulated historical release fixtures, migration packets, privacy exports, version-specific no-browser suites, and fragmented release notes. Reducing those files directly would be unsafe because several historical files still act as regression anchors.

v1.1.0-alpha.3 is an audit-only planning gate that creates a machine-readable retention registry so the project can later consolidate files without deleting active safety coverage.

## Retention rules

### KEEP_ACTIVE

Runtime, UI, backend, and unclassified files remain active unless a later release proves they can be reduced safely.

### KEEP_SECURITY

Privacy, provider, source, backend, browser, and hosted-demo tests remain explicit gates. These are not merged until equivalent registry-based coverage exists.

### MERGE_TO_REGISTRY

Candidate groups:

- `fixtures/migrations/*.json`
- `fixtures/privacy/*.json`
- `tests/v*-no-browser-suite.mjs`

These are the highest-value reduction targets, but consolidation is postponed until reference mapping and replacement tests exist.

### ARCHIVE_DOCS

Candidate group:

- `docs/v*.md`

Historical release documents can later be merged into timeline-style release-history documents after doc references are mapped.

### DELETE_ONLY_IF_UNREFERENCED

Candidate groups:

- generated CI artifacts
- Playwright reports
- test results
- old ZIPs outside official evidence/release archives

Deletion is still blocked in this release.

## Acceptance criteria

- The audit can classify representative project files.
- Direct deletion count remains zero.
- Migration/privacy/version-suite reduction candidates are visible.
- Historical docs are classified as archive candidates.
- Generated artifacts are classified as delete-only-if-unreferenced.
- v1.1.0-alpha.2 fixtures remain present as audit baselines.
- v1.0.30 public-demo freeze boundaries remain preserved.

## Disproven if

This release is invalid if:

- any file is deleted;
- runtime behavior changes;
- provider/OAuth/backend/source/storage behavior changes;
- a cleanup candidate is treated as safe to remove without reference checks;
- historical safety tests are removed before equivalent registry coverage exists;
- migration or privacy fixtures are merged before export/privacy/migration gates are remapped.
