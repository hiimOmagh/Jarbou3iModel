# v0.16.0-beta — Provider Mode Browser QA + Privacy Export Tests

## Purpose

v0.16.0-beta converts the v0.15 portable-account mock flow into a more testable provider layer. The release does not add real OAuth or live portable-account calls. It adds browser QA and export-time privacy enforcement.

## Implemented checks

- Provider selector browser coverage for `mock`, `openai_compatible`, `backend_proxy`, and `portable_oauth`.
- Portable OAuth mock connect/refresh/dry-run browser coverage.
- BYOK fake-key browser test confirming the key is never rendered into the UI.
- Privacy export guard that redacts sensitive fields before JSON download.
- Repository-level privacy audit for export, provider, portable, workflow, and fixture candidates.

## Privacy export policy

Allowed derived fields:

- `token_hash`
- `input_fingerprint`
- `prompt_fingerprint`
- `key_exported:false`
- `raw_token_exported:false`
- `access_token_exported:false`
- `refresh_token_exported:false`

Redacted fields/patterns:

- raw access tokens
- raw refresh tokens
- API keys
- bearer strings
- provider secrets
- client secrets
- private keys
- credential/password fields

## Commands

```bash
npm run test:privacy:guard
npm run test:privacy:export
npm run test:privacy
npm run test:browser:provider
npm run test:v018
```

## Boundary kept intentionally

This release does not implement real OAuth, real BrainLink/OpenRouter integration, live portable-account inference, or billing. It only prepares the UX/test/privacy envelope.

# v0.17.0-beta — State Migration + Version Compatibility Layer

## Goal

Protect the research packet format from schema drift by adding an explicit migration layer before packet validation and import.

## Added

- `src/research/migrations.js`
- `packet_migration_report` in exported workflow packets
- migration fixtures for `v0.11.0-beta` through `v0.16.0-beta`
- `tests/migration-check.mjs`
- `tests/no-browser-qa-suite.mjs`
- `tests/v018-no-browser-suite.mjs`

## Behavior

Import now follows this order:

```text
raw packet → migrateResearchPacket() → validateWorkflowPacket() → state assignment → render/export
```

Migration defaults missing fields safely, disables live calls, disables remembered keys, renumbers evidence IDs, repairs causal-link evidence references, and attaches a report to the packet.

## Privacy rule

Migration is also a security boundary. Sensitive provider fields such as API keys, raw tokens, bearer values, secrets, and credential-like keys are redacted during migration. Exports still pass through the privacy export guard.

## Non-goals

- no real OAuth
- no real source crawling
- no provider capability expansion
- no UI refactor

This release is a stability layer, not a feature expansion.

# v0.24.0-beta — Export Pack v2

## Purpose

Export Pack v2 turns a research workflow into a professional handoff bundle instead of a single opaque JSON file.

The bundle is designed for:

- GitHub archival
- Claude / ChatGPT handoff
- local research archive
- publication pipeline preparation
- privacy/security audit trails

## Export artifacts

The pack generates these artifacts as separate browser downloads:

```text
export-manifest.json
research-packet.json
analysis-brief.md
evidence-matrix.csv
review-queue.csv
provider-run-ledger.json
quality-report.json
privacy-audit.json
```

The original planned core bundle remains intact:

```text
research-packet.json
analysis-brief.md
evidence-matrix.csv
review-queue.csv
provider-run-ledger.json
quality-report.json
privacy-audit.json
```

`export-manifest.json` is added as a machine-readable index for file names, MIME types, byte counts, checksums, topic, quality readiness, and privacy release-gate status.

## Privacy model

# v0.28.0-beta — Real Portable OAuth Spike

## Purpose

This release adds a controlled OAuth 2.0 Authorization Code + PKCE spike for the portable account provider mode.

The feature is intentionally not production OAuth. It is a dev spike that proves the architecture can:

- generate a real PKCE `code_verifier` and S256 `code_challenge`
- build an authorization URL
- parse a redirect callback
- exchange an authorization code through the backend
- sanitize token responses into hashes/status metadata
- reject refresh until a server-side token vault exists
- export no raw access token, refresh token, authorization code, or PKCE verifier

## Standards basis

PKCE uses the S256 transform:

```text
code_challenge = BASE64URL-ENCODE(SHA256(ASCII(code_verifier)))
```

Browser OAuth remains risky if tokens are exposed to frontend state. This spike therefore keeps the verifier in `sessionStorage` runtime state and returns only sanitized token hashes from the backend.


`/api/oauth/token-exchange` performs a dev authorization-code exchange against an allow-listed token endpoint.

```text
oauth_refresh_requires_token_vault
```

# v1.0.23 — CI Result Review + Browser Evidence Artifact Audit

## Observation

## Diagnosis

Evidence upload is not release approval. The exact audit phrase is: evidence upload is not release approval. A browser evidence artifact can exist even when a job fails, is stale, or was generated by a workflow that does not match the current source archive. GitHub Actions status must therefore be reviewed against the exact commit SHA that will be released.

The public repository audit performed during this patch found a release-alignment risk: the visible public GitHub Actions run for `hiimOmagh/Jarbou3i_Model` still showed an older workflow shape using `actions/checkout@v4`, `actions/setup-node@v4`, `node-version: 22`, and `npm install`. That public state does not match the uploaded v1.0.22 source archive, which already contains Node 24, deterministic `npm ci`, split no-browser/browser jobs, and evidence artifact upload discipline.

## Correction

- exact GitHub Actions run URL and commit SHA;
- no-browser job status;
- browser job status;
- Node 24 workflow shape;
- deterministic `npm ci --no-audit --no-fund --ignore-scripts` install path;
- Playwright installed once before `PLAYWRIGHT_SKIP_INSTALL=1 npm run test:ci:browser`;
- browser evidence artifact exists and is inspectable;
- artifact upload is treated as inspection data, not release approval;
- external deployed/public repository state matches the release archive before public release.
