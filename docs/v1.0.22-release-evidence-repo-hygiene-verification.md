# v1.0.22 — Release Evidence + Repo Hygiene Verification

## Observation

v1.0.21 migrated the CI workflow to Node 24 and preserved the browser CI installation boundary. The next release risk is not feature capability; it is whether release evidence, repository hygiene, and tracked-file deletion requirements remain explicit enough to prevent stale artifacts or unverifiable release claims.

## Diagnosis

ZIP extraction alone cannot prove repository deletion. A file absent from an extracted archive can still be tracked in Git unless removed through `git rm`. Browser evidence can also be uploaded while CI fails, so release documentation must distinguish evidence capture from release approval.

## Correction

v1.0.22 adds a release evidence and repository hygiene verification layer. It checks that:

- Node 24 workflow migration remains intact.
- Browser CI still installs Playwright once, then uses `PLAYWRIGHT_SKIP_INSTALL=1`.
- Hosted demo evidence artifacts are uploaded for inspection without becoming a pass condition by themselves.
- Orphan cleanup commands remain documented.
- v1.0.22 fixtures and migration targets are present.
- Manual/private mode remains default.
- No live scraping, real OAuth, provider expansion, or backend endpoint expansion is introduced.

## Validation

Required gates:

```bash
npm run test:release:evidence
npm run test:v122:no-browser
npm run test:ci:no-browser
npx playwright install --with-deps
PLAYWRIGHT_SKIP_INSTALL=1 npm run test:ci:browser
```

## Compatibility boundary

This patch is verification-only. It must not alter provider behavior, OAuth behavior, backend endpoint behavior, source connector behavior, storage behavior, or user-visible product capability.
