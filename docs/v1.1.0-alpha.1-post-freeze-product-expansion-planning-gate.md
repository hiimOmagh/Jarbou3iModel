# v1.1.0-alpha.1 — Post-Freeze Product Expansion Planning Gate

## Release purpose

This release starts the post-freeze development track after the v1.0.30 public-demo visual freeze. It is a planning gate only. It does not implement new runtime capability and it does not expose roadmap concepts as available product features.

## Baseline

- Freeze baseline: v1.0.30 — Mobile Header Geometry Lock / Final Public Demo Visual Freeze
- Current track: v1.1.0-alpha.1
- Release type: alpha planning gate

## Planning gate only

v1.1.0-alpha.1 defines the lanes that may be expanded after the public-demo freeze, but implementation remains blocked until each lane has explicit acceptance criteria, falsifiers, privacy/security review, and browser evidence requirements where applicable.

## Planned expansion lanes

1. UX polish and density reduction
2. Real provider path threat model
3. Source and evidence strategy
4. Privacy/security hardening backlog
5. Release operations and artifact discipline

## Preserved boundaries

- No live scraping.
- No real OAuth.
- No live provider execution.
- No backend endpoint expansion.
- No source connector expansion.
- No storage model change.
- No automated source verification.
- Manual/private mode remains the default.
- Source packets remain local/manual drafting scaffolds unless a later implementation release changes that with explicit tests.

## Blocked claims

Do not claim any of the following in public demo material:

- live web scraping
- production OAuth/account login
- automated source verification
- real provider execution
- source connector automation
- release approval from screenshots alone
- release approval from ZIP existence alone

## Acceptance criteria

- `package.json` and `package-lock.json` identify `1.1.0-alpha.1`.
- `index.html` shows `v1.1.0-alpha.1 · Post-Freeze Product Expansion Planning Gate`.
- `src/research/post-freeze-planning-gate.js` exports a planning gate with `implementation_allowed: false` and all runtime behavior-change flags false.
- v1.0.30 freeze artifacts remain present as the baseline.
- migration support includes `1.0.30` before `1.1.0-alpha.1`.
- no-browser CI runs `tests/post-freeze-planning-gate-check.mjs`.

## Disproven if

This release is invalid if it enables any new runtime capability, exposes a planned lane as a usable feature, removes the v1.0.30 freeze baseline, or weakens provider/OAuth/source/privacy/export boundaries.
